# Repository worktree snapshot contract

This increment collects real local repository text for the existing read-only policy tools. It adds no optimization object, provider route, automatic discovery, adoption action or live filesystem tool. The developer entry explicitly selects a repository root and exact files. Fixed-response execution checks transport and isolation, not answer quality on arbitrary repositories.

## Selection and capture

- The host supplies an absolute existing checkout root containing a regular `.git` file or directory (including linked worktrees). Canonicalize the root once; reject a symlink root. Do not invoke Git, read its configuration/index/object database, run filters/hooks, traverse submodules, or infer selected files from Git status/ignore rules.
- Selection is 1–32 unique exact relative file paths, ordered by UTF-8 bytes. Reuse the policy file contract: at most 256 KiB per file and 1 MiB total, valid UTF-8 without NUL. Preserve raw UTF-8 bytes, including BOM and line endings. No directories, globs, absolute paths, traversal, backslashes, controls, symlinks, hard-linked files or special files. No implicit dependencies or fallback files. An invalid/denied selection fails the whole capture; never silently shorten the manifest.
- Deny common VCS metadata, dependency/cache/runtime-home and credential paths before opening selected files. Deny `.env*` (including examples), credential/secret/token filenames, private key and local database/log formats. Apply a conservative content guard for private-key blocks, common credential literals and recognizable token formats before returning or sealing any content. Errors identify a path/reason only, never the rejected bytes. These guards are defense in depth, not a complete secret detector. Explicit file review is still necessary before any future external disclosure.
- Use bounded read-only, no-follow, nonblocking file descriptors. Check canonical ancestry, regular-file identity, link count, size and nanosecond modification/change metadata before and after each read. Repeat all selected reads and compare bytes/identity before returning. Normal concurrent edits, replacements, deletion or path changes fail closed. Writers should be quiescent. This is a checked multi-file capture, not an atomic filesystem snapshot or an OS security boundary against a hostile concurrent host process.
- Capture current worktree bytes, including explicitly selected tracked edits and untracked/ignored files that pass scope checks. Do not stage, stash, checkout, reset, chmod, write repository files or invoke project code. A commit ID is not the snapshot identity. File permissions, Git status, timestamps and unselected files are not model input.

## Sealing and binding

`RepositorySnapshot` is strict `{schemaVersion: 1, kind: 'repository-worktree', root, files: [{path, content}]}`. `root` is canonical absolute provenance. The content digest is SHA-256 over compact canonical parsed JSON, including the sorted exact paths and unnormalized text. A derived review manifest contains path, UTF-8 byte count and raw content SHA-256; it adds no independently editable source of truth. Capture returns detached bytes; sealing this value does not reread a later worktree state.

Store objects under a dedicated `repository-snapshots/<digest>.json`. Reuse policy object publication: private staging file, file flush, read-only permissions, non-replacing link, verified canonical read and directory flush. Reads reject symlinks, writable/nonregular/oversized or changed/corrupt objects. A complete orphan is safe to reuse only after full validation; never replace a conflicting object.

Policy conditions gain optional `sourceSnapshot: {root, digest}`. Its digest must exactly reconstruct the snapshot from those conditions' files, with the same scope validation and order. `conditionsDigest` therefore covers provenance and content. The host loads a sealed object to construct conditions; workers receive only frozen text, never an instruction to open `root`. Changing worktree files, root, selected paths or bytes creates a different snapshot/conditions digest. Existing conditions without this optional field keep their original bytes/digests and behavior. No SQLite schema change or rewrite is required.

The fixed casebook remains unchanged. Real-repository capture does not qualify a new case for that evaluator or for sidebar adoption. Do not reuse its fixed-case answers to claim arbitrary-repository correctness. Existing version adoption/restoration and immutable old-session bindings remain unchanged.

## Failure and recovery

Abort, missing/unreadable/denied/changed/oversized/non-text files return no usable snapshot and make no model request. Always close acquired descriptors. Publication failures remove only the staging file owned by that call, and never delete an existing target. Abrupt process loss can leave a `.seal-*` file or a complete unreferenced object; neither grants execution authority. Retry from an explicit selection, validate any complete existing object and leave unknown staging files untouched. No startup directory sweep, silent replay or historical deletion.

The command stores each run in a unique owned local directory. Capture/sealing is free. Its optional `--verify` action uses only the existing offline native subprocess fixture, frozen route/budgets and ledger: literal search, exact first selected file read, tool-result continuation, final response, verified Agent/process/home cleanup. It has no real provider or ambient credentials. A failed verification preserves the sealed object and failure evidence for review. Large snapshots may exceed the separately fixed tool/input limits and must fail visibly rather than broaden them. Future repository comparisons need their own externally frozen questions/answers and full-task authorization.

## Acceptance

Prove exact file selection and deterministic digests; path/content sensitive exclusions; symlink/hardlink/special/binary/size rejection; selected dirty and untracked bytes preserved independently of later edits; cancellation and mid-capture mutation failure; corrupt/conflicting publication and process-loss retry; unchanged historical conditions/digests/SQLite rows; and a full native fixed-response task reading real captured source with owned resource cleanup. No paid calls.

## Sidebar selection and dedicated sessions

The sidebar selects exact workspace-relative paths, one per line, under an already registered workspace. It cannot supply a host root, content, policy, route, budget or snapshot digest for a new preview. Reuse the existing capture scope/guards; reject the complete selection on any error. No directory traversal UI or automatic scan is introduced.

`policy_preview` binds workspace, expected active choice ID, exact paths, operation ID and current global revision. The host checks authority before capture and again when committing. A persisted preview freezes the captured files, source provenance, question text and the approved batch's existing offline route/limits as complete conditions. A preview is not a sealed source or execution authorization. The browser shows the complete captured text, file byte counts, selected policy and limits before confirmation. Only a specifically requested preview body is returned; normal sidebar snapshots include metadata, not every source body.

`policy_seal` binds workspace, preview ID, exact snapshot digest and expected active choice/revision. Before publication, recapture the same exact files and require an identical snapshot. A changed file, sensitive-content change, workspace move, policy change or stale state requires a fresh preview. Publish only the reviewed bytes; mark sealed and record the operation receipt in one transaction. File publication can precede a failed transaction; the unreferenced object has no session authority. Retry validates it without replacement. Lost successful replies return the original receipt before recapture or stale checks. Cancelling the confirmation makes no host mutation.

`policy_source_session` separately binds the sealed preview ID/digest and current choice/revision. It requires the preview's exact original policy choice and intact approval proof/object. Create the immutable session binding and receipt before native Agent provisioning; this action never dispatches a model request. The first user message is a separate action under the displayed fixed-response route and cumulative limits. Unknown/interrupted usage blocks continuation as before. No automatic real-provider fallback exists.

Append `policy_sources` to the unreleased SQLite 7 path. Rows contain host identity/workspace/choice, complete frozen conditions, creation time, `preview | sealed` status and nullable seal time. Only the seal transition can update a preview; sealed rows are immutable. Existing business JSON, terminal historical rows and sessions are not rewritten. `policy_sessions` gains optional `sourceId`; absent means the historical evaluated-batch source. Present means that exact sealed source's conditions digest. Startup validates source/choice/receipt/binding relationships without silently repairing data. A missing/damaged selected source object fails session creation/resume/dispatch; no fallback to live files, another source, or the evaluation sample. Keep database and repository-snapshot objects together in backups; old strict builds need the complete stopped-host backup for downgrade.

The row ID is its preview operation ID. `sealId` is null for previews and identifies the exact successful seal receipt for sealed rows. Normal sidebar snapshots expose only source metadata and derived manifests; `/rsi/policy_source` returns one validated full preview for its registered workspace. `policy-inputs.ts` owns browser-safe structural fields/file guards; host `policyConditionsSchema` additionally verifies SHA-256 provenance before persistence, source-body reads and dispatch. The host freezes the approved route and limits into the preview; source collection limits do not enlarge tool-result or request limits. The preview displays its canonical workspace path, exact policy choice, complete files and limits.

Changing workspace clears source bodies and pending confirmation. Earlier sessions retain their original source and policy even before their first request, after new previews/seals/adoptions, after restart, and after worktree edits/deletion. Failure before commit leaves no new authority; failure provisioning a committed session leaves a recorded binding that can be opened/recovered. Restart never captures, seals or sends a request automatically. Preview capture is cancellable on host disposal; outstanding owned work must finish/abort before store shutdown.
