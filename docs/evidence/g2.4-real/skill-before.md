# 前端页面设计

先阅读当前项目与用户需求，使用已有技术栈和组件。新建页面时确认产物位置、页面用途、必需内容及交互；缺少会影响交付的信息时简短询问。只在用户授权的位置修改页面文件。

## 使用设计上下文

如果任务提供 RSI 冻结的设计上下文，使用其中的页面需求和有效偏好。它记录了本次、项目、个人偏好的合并结果；不要自行扩大作用范围。`skip`、`no_preference` 和 `unspecified` 表示没有可执行的审美要求，不要编造用户喜欢的风格。

用户最新明确要求优先；它与上下文、功能要求冲突时先指出具体冲突并确认。审美偏好不能免除功能、可访问性或用户指定的信息。没有上下文时，只问少量会改变设计选择的问题，允许用户跳过；不要宣称已经读取或保存了插件偏好。

## 实现页面

1. 明确阅读顺序、主要行动和必要信息，再安排布局、间距、文字层级和强调色。将抽象偏好转成页面中的具体选择，不以模板风格替代用户要求。
2. 用语义结构、可读对比度、表单标签、键盘焦点和合理的窄屏布局。动效遵循减少动态效果设置。交互必须有可验证的行为，不能留下看似可点击却没有作用的按钮。
3. 复用可用资源。外部图片、字体或依赖需符合任务允许的网络与资源范围；没有产品事实时使用明确的虚构文案或占位内容，不编造客户、销量和评价。
4. 核对必需内容与交互，检查窄屏、长文本、键盘操作和动效设置。说明实际执行的验证及其限制；没有查看页面时不声称视觉验收通过。

## 交付与反馈

简洁说明产物位置、关键设计选择、验证结果和仍需确认的点。用户反馈只作为当前修改依据；持久保存偏好由 RSI 界面中的明确选择完成。

不要自行修改本 Skill、授权、预算、评测器或有效版本。新的 Skill 只能由独立的 RSI 优化任务在获准范围内形成候选；页面符合偏好不等于 Skill 能力已提升。
