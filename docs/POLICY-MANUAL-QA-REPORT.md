# Manual repository question pack gate

2026-10-16. Base `8f62c0907c21bea48fb36b5e31c2b9f1dddcc802`, branch `codex/policy-manual-qa`. [Contract](POLICY-MANUAL-QA-CONTRACTS.md) · [evidence](evidence/policy-manual-qa/README.md). Fixed responses only; zero paid calls.

## Implemented

The existing source sidebar now accepts human-authored symbol, call-chain and error-path questions. Native fields capture unique fact keys, exact standard answers, selected snapshot files and line ranges. Every save appends a draft with optional parent provenance. Review displays all three saved questions, answers and the actual cited sealed text. A separate explicit confirmation seals that exact draft; editing a sealed pack saves another draft. No pack action authorizes generation, evaluation, adoption or a session change.

`policy-qa-inputs.ts` is the shared executable content boundary. `policy-manual-qa.ts` validates snapshot identity and cited lines, derives required reads from citations and freezes one question. An additive `policy_qa_packs` table and existing canonical read-only JSON publication retain draft/seal authority and receipts. Startup verifies source/parent/draft/seal references without rewriting historical rows. Failed publication transactions leave an inert object with the draft and authority unchanged; explicit retry can complete. The new authenticated read serves full packs only in their registered original workspace. Pack long-poll metadata contains no questions or standard answers.

An optional exact pack ID/content digest plus case ID extends the existing independent evaluation command. The new concrete spec pins source ID, pack record/content, case, expected answer, required reads and both runs' conditions. Generation still receives only its original baseline/requirements/development example. Workers receive no spec or answer pack. The existing two-child executor, native search/read tools, continuation evidence, one ledger, cumulative limits, unknown usage, stop/recovery, cleanup, adoption and immutable session binding are reused. Complete quality failures remain distinct from incomplete execution. Pack integrity is checked before dispatch and QA-bound session use; changing the latest draft cannot change an old batch or its approval.

## Preservation, cleanup and limits

All 150 pre-existing tracked evidence/fixture files retain their original hashes. Harness HEAD and the pre-existing binary patch are unchanged. No historical user database was opened, cleared or reset. Private diagnostic profiles, sealed objects and ledger remain under `.cache/`, excluded from the package. Human-authored standard answers still require human factual review. Existing fixed exact-value/citation checks establish conformance to that reviewed pack; scripted responses establish execution/authority/accounting/recovery behavior, not model improvement or automatic semantic truth. Each case remains a separately authorized pair. The pack supports sufficient answers and at most three cited files per question; larger tasks need a concrete budget/read contract. The current route remains fixture-only. SQLite remains unreleased v7; older strict readers may reject new commands/specs. Downgrade requires the complete stopped-host backup, including question objects. No new execution framework, dependency or paid permission was introduced.
