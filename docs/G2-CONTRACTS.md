- 模型输出为 candidate、clarify 或 unchanged，严格拒绝其他字段。澄清最多两批、每批三问，`flow_answer` 只接受当前批次，延续原截止时间与账本。扩大范围必须结束并重新确认；历史消费不清空。
- 候选固定检查为完整清单、授权路径、非空、保留原 SKILL.md 元数据，以及固定 Docker 内 Python AST / Shell -n。不执行候选提供的检查器；Docker 不可用不回退宿主。无脚本记不适用，页面功能/效果对照记未评测，不伪造 G3 通过。
- 状态为 confirming → generating → checking → review → ready → dispatched；澄清为 clarifying，失败为 failed，停止为 stopped。`flow_choose` 只接受精确候选摘要及预期旧 ACTIVE；未知 usage、未完整响应、检查失败均不能启用。旧版继续重新校验基线。
- 项目 ACTIVE 按工作区与 Skill 保存，scope=task 不更新项目指针；个人范围只推广已确认偏好，新版 Skill 仍只启用于当前项目。当前 Skill 原目录始终保留。
- 页面文本和资源绑定同一封存摘要。已有不同版本时用确定性 ID 建立关联会话，继承本次已确认需求与偏好，不复制旧 Skill 或旧工具输出。旧绑定不可改写。投递前持久记录 queued，接纳前记录 admitted；重复确认不多创建、不重复投递。

## 偏好驱动的独立修改任务

2026-09-08 用户确认：同一张卡确认偏好、Skill 修改范围和预算，随后自动生成候选；候选完成检查并经用户确认后，再用新版开始本次页面任务。本节为用户确认的产品依据；g2.3 的可执行字段与本轮适用边界以上方执行细化和主流程报告为准。

### 输入与模型职责

用户明确的偏好直接构成修改方向，不要求先命中观察规则，不强制经过一次仅输出建议的模型分析。复用 Harness provider 和独立任务上下文，模型负责理解偏好、澄清具体歧义、修改 Skill 候选。宿主负责冻结输入、派发额度、文件校验、状态、评测和启用；不预设“某个偏好必须对应哪段改写”的规则表。

实现前需在一份可执行定义中确定下列最小数据，类型从定义推导，不预建其他 Gate 的完整对象：

| 数据 | 本阶段约束 |
|---|---|
| 目标与版本 | 工作区、页面任务/会话、受管 Skill、起始文件清单及版本摘要；模型不能指定另一个目标 |
| 偏好输入 | 用户原文、明确作用域、已确认的适用偏好和必要澄清答案；自由文本不必归入固定六类；保留原文，模型概括不自动替代用户确认内容 |
| 修改授权 | 用户提交确认卡的记录，绑定完整输入摘要、具体可修改路径、模型路线、检查条件和预算；只纳入观察或只保存偏好不能创建此记录 |
| 候选 | 父版本摘要、授权内文件变更及修改理由；宿主校验和封存后生成候选摘要；未变文件从基线保留，禁止用不完整模型响应覆盖文件 |
| 检查结果 | 检查器及输入引用、逐项完成状态、错误与证据；模型自报通过不作为通过依据 |
| 启用与执行绑定 | 用户审阅的精确候选摘要、预期旧有效版本、目标会话绑定；未经确认的候选不能进入本次页面执行上下文 |

生成阶段必须能取得待修改文件的完整内容，或通过授权内只读资源访问取得完整内容。当前 `prepareInput` 的分析片段只能作分析，不可当成完整待覆盖文件。超过已确认输入/文件限制时停止并说明，不静默截断后改写。Python、Shell 与模板仍属于可授权范围；它们的执行和模型生成的检查必须进入已验证的 Docker 边界，不能借正常页面 Agent 在宿主上提前执行候选。

模型输出可以是候选变更、需要澄清或有理由的无需修改。无需修改不能伪造新版或提升证据；它与生成失败、用户拒绝的后续页面处理都必须明确展示。实际模型路线、请求数、输出上限、Token 停止阈值与执行环境在实测前冻结，本节不新增付费批次。

### 交互与状态转换

主路径为：`等待确认 → 生成候选 → 检查候选 → 等待启用确认 → 就绪并开始页面任务`。偏好确认、修改授权合用一张卡；启用精确候选是后续单独动作。

- 等待确认：展示偏好、范围、检查与预算，尚未提交时不派发修改请求。用户选择纳入观察仍保持其原义，不把旧 Enrollment 迁移成修改许可。
- 生成候选：一次任务授权内调用独立模型。必要澄清返回等待回答，每批最多 3 问、最多 2 批；回答仅在原方向和文件范围内可继续，扩大范围或改变已冻结目标需重新确认，旧消费不清零。
- 检查候选：内容和脚本检查、固定必需条件与适用页面评测分别记录；候选不完整、关键检查失败或用量未知时不能进入可启用状态。用于检查的隔离页面属于 RSI 评测产物，计入 RSI 预算，不是提前在用户项目中开始正式页面任务。
- 等待启用：展示完整差异、理由、检查结果、已知限制和消费；仅精确候选得到用户确认后提交启用。用户等待期间释放执行进程和容器，不以等待为由延长已授权调用窗口。
- 开始页面：在首次页面请求之前固定 Skill 文本和脚本/资源的同一候选摘要，再交给 Harness 正常执行。RSI 修改、澄清与评测分别计入 RSI 账本；正式页面编写计入日常会话。
- 取消、失败或中断：保留原因、候选与已有账本，停止依赖请求，清理本任务资源；重启不自动重新调用模型。用户已确认候选生成/检查失败、预算耗尽或拒绝新版时保留旧版，展示“用旧版继续”与“停止本次任务”，等待选择，不自动回退。

“用旧版继续”核对本次起始版本仍完整可用，在该版本上开始或继续页面执行，不重试 RSI、不重置已消费额度；页面执行仍计入日常会话。“停止本次任务”取消本次 RSI 与等待中的页面启动，保留已有页面文件和历史，不影响其他任务。它与 g2.2 的“结束本次任务”（只结束 RSI 观察）语义不同，实现时必须用明确说明区分。

### 首次绑定与已有会话

用户已确认“本次页面用新版”，因此在首次页面请求之前保留等待边界。g2.2 的 `agent/pre-step` 在返回前可等待原生问答；Harness 原生 `/Skill` 解析也可能已在该次待提交消息中形成旧版 Skill 文本。下一实现必须重新组织待提交内容，验证旧版没有随新版一起进入实际请求，并保证资源路径与文本来自同一版本。仅改磁盘文件或只更新面板版本号不算完成接入。

用户已确认：已有会话若已经使用过旧 Skill，自动创建关联新会话，带入本次需求和确认偏好，再用已批准的新版继续。旧会话与原绑定保留。使用 Harness 会话创建能力建立关联，不整段 fork 旧模型上下文；带入的是本次需求、必要项目约束、确认偏好和来源引用，旧 Skill 指令、旧工具输出不自动复制。新会话继承本次任务的已确认选择，不再重复询问是否纳入；这一继承只适用于宿主为同一任务创建的关联会话，用户另开任务仍需重新确认。

创建、绑定与派发须可幂等恢复：重复点击不能创建多个关联会话或重复执行页面任务。关联创建失败、基线/候选资源缺失或上下文不足时保留可恢复状态，不把旧会话切为新版，也不悄悄丢掉必需要求。新的执行会话必须在首次请求中使用已确认候选，停止本次流程时同时阻止尚未派发的关联任务。

### 验收与兼容

最小受控验证覆盖：确认前无修改派发；明确偏好不依赖观察信号；模型候选实际改变授权文件且保留其他文件；重复提交不多派发；越界/损坏输出拒绝；澄清与失败不重置预算；取消/重启保留消费；启用前无正式页面请求；启用后实际模型上下文和资源全部使用用户确认版本；旧会话保持旧绑定。

现有六维偏好、设计快照、分析、草稿、观察 Enrollment 和历史回执保留原义，后续迁移不得补造修改或启用许可。当前文件下方描述 g2.2 已实现契约；新任务对象和数据库迁移随实现同时落地。本段将单候选生成、检查、人工启用和本次任务衔接作为完整交付路径，复用已有 G0 能力；各 Gate 的隔离、效果和恢复证据仍分别验收，不将路径写入文档视为 G2–G4 全部通过。

## 当前字段与权威定义

可执行定义位于 `src/frontend-contracts.ts`，命令与 G1 现有事务、修订及回执合用。所有文本有长度限制，拒绝多余字段。

| 对象 | 字段及约束 |
|---|---|
| Preference | 宿主 UUID、修订、`project/personal`、项目 ID 或 null、六类维度之一、用户确认文本、是否启用；最多 768 条。相同作用域与维度只有一条当前记录 |
| DesignTask | 宿主 UUID、修订、受管 Skill/工作区/版本摘要、用户输入的页面需求、`collecting/ready/closed`、至多两批固定问题、至多六项本次答案、冻结快照与摘要、创建时间；最多 256 条，同一 Skill 至多一个未结束准备任务 |
| Answer | 问题维度、`value/no_preference/skip`、文本或 null、`task/project/personal` 保存范围。跳过或无偏好只能作为本次答案，不自动写入持久偏好 |
| FrozenDesign | 需求、Skill 版本、按固定顺序记录的六项有效偏好、来源作用域与记录修订；未指定或跳过以 null 明示。摘要绑定全部快照内容 |

第一步暂不增加页面类型条件或自动语义冲突识别：跨页面类型规则可写入用户确认文本，宿主只做作用域合并；模型分析可指出语义冲突，不能自动覆盖偏好或放行硬性检查。此前已确认的完整产品边界仍见 FRONTEND-SCENARIO.md。

## 命令与状态

- `design_create`：核对受管来源、版本和登记工作区后创建准备任务。仅对缺失维度生成第一批最多三问，不调用模型。
- `design_answer`：只接受当前未作答批次的全部问题，拒绝重复/越界维度；回答与明确选择保存的偏好在同一事务内写入。需要时自动产生第二批剩余问题，总批数不能超过二；旧回执重放不增加批数。
- `design_override`：确认上下文前可对继承或已作答的维度作本次覆盖，也可表示无偏好或跳过；当前未回答批次中的问题仍通过 `design_answer` 提交。此命令不修改持久偏好、不追加提问批次。
- `design_finish`：用户确认设计上下文，可跳过尚未回答的可选审美问题，使用明示的未指定值；生成不可变快照并进入 ready。完成准备不授权修改或调用模型。
- `design_close`：结束当前准备，保留答案和快照；有依赖它的运行中分析时拒绝，先取消或等待该分析结算。关闭后旧的分析预览不能开始。
- `preference_save`：用户明确保存项目/个人偏好，支持修改与启用/停用。作用域或项目变更不能伪装成原记录更新。
- `preference_remove`：移除当前偏好记录，不清空已冻结任务与操作回执中的历史语境，不宣称删除了所有历史数据。

已确认答案不重复询问。任务答案优先于项目、个人及未指定值；用户在当前任务选择无偏好或跳过时不被继承值覆盖。持久偏好修改可供尚在 collecting 的准备与后续准备继承，不修改 ready 快照。已确认后需要新的偏好条件时结束本次准备、重新确认上下文；这不能重置任何已有模型调用额度。

G1 `prepare_analysis` 可选择一个 ready 设计任务，将完整冻结设计内容放入原有的发送预览；分析记录绑定设计任务 ID/摘要。开始分析与保存草稿时重新核对关联任务仍可用；用户仍须确认输入及现有的一次模型预算。新增 `design` 方向只表示偏好适配建议，不能作为审美分数或改进证明。

用户也可通过 `prepare_design_analysis` 直接预览 ready 设计任务的分析。此时 `opportunityId` 为 null，设计关联非空，不伪造日常会话事件或缺陷线索。两条入口共用发送预览、脱敏、字节上限、预算及一次请求账本。脱敏后的实际发送文本以预览为准，设计摘要绑定原始确认快照。

## 存储与接入

### 任务开始时主动纳入（2026-09-08 交互调整）

用户要求在前端编写开始前询问是否纳入自我迭代，并确认默认只覆盖本次任务。常用入口改为普通 Harness 输入框；手动登记与设计准备保留在高级设置。纳入仅允许记录本次任务线索，不授权修改、模型分析或启用。

宿主在 `agent/pre-step` 识别明确的前端 Skill 调用或本地规则命中的前端编写需求，通过已有 `userQuestions` 问答暂停首次模型请求。明确指定 Skill 时展示实际名称；尚未指定时展示目录中可用的前端 Skill 作为选项，只有用户选定后才注入所选 Skill。选择暂不纳入则保持原任务继续，不注入建议 Skill。模型中途调用前端 `skill` 时通过工具前置钩子补问；这一补问只能保证 Skill 加载前暂停，不能证明此前没有模型请求。分类规则不是任意自然语言意图识别。

新增 Enrollment：UUID、会话 ID、起始 turn、工作区 ID、`included/declined`、Skill ID 或 null、`active/ended`、创建时间；最多 512 条，每会话至多一条 active。同一任务内不重复询问，不接受自由文本作为纳入授权；结束、取消或卸载时不能将未回答写为同意。回答后重新核对来源和工作区，纳入副本与任务记录在同一事务提交，原 Skill 不改写。新会话不继承本次选择。

用户已确认：同一会话内连续修改沿用本次选择；新会话，或点击“结束本次任务”后再次询问。此入口结束的是 RSI 观察范围，不停止普通编写任务。

持久层升级为 SQLite 版本 4，在版本 3 业务状态补入空 enrollments，旧请求、回执及前端快照保留。原生问答由运行时管理，不把未结束问答作为重启后的隐含授权。无交互回答器或中途取消时不派发依赖此确认的模型请求。只在实际根 Agent 提问，后台子 Agent 不申请扩大权限。

核对历史会话所属工作区时，优先使用已加载会话的不可变 header；会话尚未加载则通过 Harness `sessionPersistence.stat` 读取持久 header，不加载完整聊天、不接管会话。不存在或工作区不匹配仍拒绝，持久读取失败保留错误；不能将尚未加载误判为工作区冲突。

此前 g2.0 使用同一 SQLite 和 G1 业务 JSON 增加 `frontend` 字段，将数据库升至 3；g2.1 在其基础上升至 4。迁移在事务内校验旧记录并补入缺失的前端状态、历史分析空设计关联及空纳入记录，保留请求、授权草稿、预算和回执。无法识别或损坏的旧记录回滚迁移，不清空；旧二进制拒绝新版本，回退须使用停机备份或独立目录。

首次安装注册随包提供的 `rsi-frontend-design` 初始 Skill。任务开始时确认纳入会自动完成登记；手动管理入口保留在高级设置。初始 Skill 不包含用户个人喜好或评测答案。单独的冻结设计上下文仍需从高级设置复制到普通 Harness 任务，当前主动纳入不自动注入偏好。

## 当前验收与后续边界

无付费验证必须覆盖：未纳入/来源变化拒绝、固定问题上限、跳过和无偏好、作用域隔离、冻结快照不随记忆改变、过期写入与幂等、重启保留、旧记录迁移失败回滚、零调用准备、一次分析的上下文归属。

真实浏览器使用隔离 profile 和固定模型响应，验证初始 Skill 发现、问题卡、偏好保存、上下文冻结及分析预览。结束后关闭本次服务和浏览器。Docker、实际页面生成及真实效果比较不以此回放代替。

首批样例暂按已提出的“虚构产品落地页＋HTML/CSS/少量 JavaScript”准备，未收到用户选择时标为实施假设。后续单候选执行前还需冻结产物清单、检查器、镜像资源、文件工具边界和调用预算；届时逐项扩展本契约，不预建未用对象。
