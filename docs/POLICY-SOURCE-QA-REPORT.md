# Fixed questions over sealed source: delivery

2026-10-16, base `96af936501b14da7abdac3013db076618575b644`. Implemented under the [minimal contract](POLICY-SOURCE-QA-CONTRACTS.md), with fixed responses only and zero paid calls.

## Delivered scope

One host-authored `repository-source-qa-v1` pack covers symbol location, a call chain and an error path. The selected snapshot must contain exactly the three repository-relative files under `fixtures/repository-qa-v1/`, with identical full contents. The snapshot comes through the existing real read-only capture/preview/seal path; the pack never replaces a user's selected source. Unsupported, shortened or changed manifests reject evaluation authorization without losing the sealed candidate or generation cost. New repositories need reviewed, versioned host questions/answers rather than automatic answer inference.

The small program contains an imported `total`, a misleading unused same-name implementation and an instruction-like comment. Symbol location checks which definition checkout actually imports. Call-chain facts cover `submit → checkout → total` and the successful result. Error facts cover the invalid-quantity guard, RangeError/message, propagation and catch/return result. Source was inspected and the trusted fixture's success/failure results were independently executed in development tests. The evaluator never executes selected/candidate source.

`policy_evaluate` adds only optional `caseId`. Each selected question authorizes one paired batch with equal frozen question, files, route, tools and per-side limits. Generation remains a separate authorization against the exact baseline/source. The proposer receives its unchanged independent development example; actual captured requests exclude the selected source, question pack, held-out answers and evaluation results. The client/worker bundles also exclude the host answer pack. Workers receive no evaluation spec/answers. Candidates still edit only literal policy instructions.

The existing checker now requires every source question's read set, alongside native search/read/result/continuation/turn evidence, fixed facts/citations, confirmed shared-ledger usage, independent processes/homes and cleanup. Every three-question fixture comparison makes four requests and three tool calls per side. The UI keeps the old six-request default, explains that these multi-file comparisons require eight, and requires an explicit budget change/confirmation; selecting a question does not raise limits. There is no automatic suite, adoption or overall winner.

## Recovery and compatibility

SQLite remains 7, with one new specification variant and optional command/projection fields. Omitted-case commands still select the unchanged first-line evaluator, without inserting defaults into historical rows. Existing six-case developer comparisons and source/session/adoption paths remain supported. Exact source/intent guards now cover both source evaluator variants, including resumed sessions. Old strict v7 readers may reject new commands/specifications; downgrade only from the complete stopped-host database/object/artifact/session backup.

Wrong facts or citations after complete execution produce failed quality checks. Missing reads/tools, unknown usage, exhausted budgets or interrupted work are incomplete and cannot pass. Duplicate operations return the original receipt; changed cases under the same operation reject. Corrupt case receipts/specifications fail startup without clearing them. Source loss after authorization blocks the first adapter dispatch. Authorization-only restart and actual controller exit after search/read preserve intent, partial requests and unknown usage without replay. Existing raw attempts, batches, generations, session bindings and command/receipt rows remain unchanged where terminal.
